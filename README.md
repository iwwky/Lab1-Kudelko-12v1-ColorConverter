# ColorConverter — вариант 1, подгруппа 10А

C++17 / Qt Widgets: RGB ↔ LAB ↔ CMYK.

## Запуск

Открыть `ColorConverter.pro` в Qt Creator, выбрать Desktop Qt kit и нажать Run.
Локально проверяется Qt 6.11.0 на macOS. Для сдачи под Windows нужно собрать этот же проект в Qt Creator на Windows (MinGW либо MSVC) и запустить `windeployqt` для готового exe. Сборка и запуск под Windows пока не проверены.

## Интерфейс

- Три модели видны одновременно. В каждой есть поля, ползунки и кнопка общей палитры.
- RGB: целые 0…255. CMYK: доли 0…1, где 1 означает 100%. LAB: L от 0 до 100, a/b от −128 до 127 — выбранный диапазон редактора, а не универсальная граница пространства LAB.
- Числовые поля применяются после Enter или потери фокуса. Ползунки пересчитывают цвет сразу.
- Фон каждого ползунка рассчитан по 25 образцам с текущими остальными координатами. Qt интерполирует между образцами.
- Палитра Qt используется только для выбора RGB. QColor не выполняет расчёты LAB, XYZ или CMYK.
- При исходном LAB вне RGB-охвата сохраняются введённые LAB-координаты; RGB, CMYK и цветной образец показывают скорректированный цвет. Появляется предупреждение. Поэтому LAB и RGB в этом случае не являются точными эквивалентами.
- При смене стратегии повторно преобразуется сохранённый исходный цвет. При смене освещения сохраняются координаты последней редактировавшейся модели.
- При ручном вводе CMYK сохраняется заданное цветоделение. Выбор UCR/GCR используется при получении CMYK из RGB или LAB; он не переписывает вручную заданные CMYK.

## Слои

- `colormodel.h/.cpp`: только стандартный C++, формулы и матрицы, без Qt.
- `colorcontroller.h/.cpp`: исходный ввод, настройки, пересчёт и признак коррекции.
- `mainwindow.h/.cpp`: элементы Qt, сигналы, вывод чисел и отрисовка градиентов.
- `main.cpp`: запуск приложения.
- `tests`: независимые математические проверки и проверки связи элементов интерфейса.

## Расчёт XYZ и LAB

RGB трактуется как sRGB. Сначала выполняется снятие гаммы, затем умножение линейных каналов на рассчитанную матрицу. XYZ нормировано так, что Y белого = 100. Наблюдатель — CIE 1931, 2°.

Матрица sRGB → XYZ не записана готовыми коэффициентами: она вычисляется из координат первичных цветов (R: .64/.33, G: .30/.60, B: .15/.06) и белого D65. Решается система для масштабов столбцов. Обратная матрица вычисляется методом Гаусса — Жордана с выбором главного элемента.

При D50/E используется хроматическая адаптация Bradford: A = B⁻¹ · diag((B·Wtarget)/(B·Wsource)) · B. Итоговая матрица A·M и её обратная заново рассчитываются при смене освещения. Это сохраняет определение sRGB с белым D65; простая замена делителей в формуле LAB не используется.

Стандартные исходные данные (первичные цвета, точки белого, базис Bradford, параметры гаммы и определения LAB) остаются числами в коде. Запрет готовых конверсионных матриц не означает запрет физических/стандартных исходных данных. Матрицы RGB↔XYZ для D65/D50/E и коэффициенты адаптации к выбранному белому не захардкожены.

LAB использует точные пороги через δ=6/29. Обратные формулы умножают X на Xw, Y на Yw, Z на Zw (в учебном PDF первые два множителя перепутаны).

## CMYK

Используется учебная идеализированная модель, без ICC-профиля конкретного принтера.
Пусть c₀=1−R/255, m₀=1−G/255, y₀=1−B/255, gray=min(c₀,m₀,y₀).

- GCR: K=gray, полная замена серой составляющей во всём диапазоне.
- UCR: K=gray·clamp((gray−0.5)/0.5,0,1). Удаление начинается только при gray>0.5 и плавно возрастает в тенях. Порог и кривая — явно выбранные параметры этой реализации: в условии они не заданы.
- C=(c₀−K)/(1−K), аналогично M/Y. Для K=1 отдельно возвращается (0,0,0,1).
- Обратный перевод R=255(1−C)(1−K), аналогично G/B.

Алгоритмы сохраняют исходный RGB при обратном переводе. Отличаются распределением между цветными и чёрной красками.

## Выход за охват

Clipping ограничивает каждый канал интервалом [0,255]. Scaling применяет одну аффинную функцию ко всем каналам: left=min(0,R,G,B), right=max(255,R,G,B), v′=255(v−left)/(right−left). Это учитывает отрицательные каналы и значения выше 255. При отрицательных каналах сохраняются пропорции разностей, а не отношения исходных каналов.

Расчёт ведётся в double; округление выполняется в интерфейсе. Отклонения менее 1e−7 возле границы RGB считаются вычислительной погрешностью и не вызывают предупреждение.

## Проверки

Математика без Qt:

```sh
c++ -std=c++17 colormodel.cpp colorcontroller.cpp tests/math_tests.cpp -o math_tests
./math_tests
```

Или открыть `tests/tests.pro` в Qt Creator. Для проверок интерфейса открыть `tests/ui_tests.pro` (нужен модуль Qt Test). Это отдельные приложения, исходный проект менять не нужно.

Автоматические проверки охватывают эталоны EasyRGB, белый и чёрный, матрицу и её обратную, 216 RGB-цветов при каждом из трёх источников, обратные LAB/RGB и CMYK/RGB, различие UCR/GCR, clipping/scaling и сохранение исходного ввода. Проверки интерфейса проверяют связь полей, ползунков, настроек и градиентов.

## Сверка с EasyRGB

2026-09-11 непосредственно в https://www.easyrgb.com/en/convert.php проверены входные sRGB 0-255, результаты D65/2°:

- RGB(255,0,0): LAB(53.241,80.092,67.203), XYZ(41.246,21.267,1.933), CMYK(0,1,1,0).
- RGB(128,128,128): LAB(53.585,0,0), XYZ(20.517,21.586,23.504), CMYK(0,0,0,0.49804).

В приложении выбрать D65 и GCR. Для LAB в тесте принят абсолютный допуск 0.002 на координату из-за округления эталонов и различий округления исходных коэффициентов; обратные преобразования проверяются с допуском 1e−6 по RGB. Точного сравнения double через == для цветовых преобразований нет.

EasyRGB не предоставляет выбор нашей кривой UCR. Его стандартный CMYK нельзя использовать как эталон UCR. Прямое совпадение с EasyRGB для D50/E не заявляется: необходимо согласовать способ хроматической адаптации; переключение опорного белого без адаптации — другое вычисление.
